# Phase 4 — Zarinpal wallet top-up

## Scope
- Gateway payments are only for wallet top-up.
- Existing order checkout continues to debit the internal wallet.
- Existing order refunds continue to credit the internal wallet.
- Amounts are integer Rial in the application and are sent to Zarinpal v4 as Rial.
- Provider-specific code is isolated behind `PaymentProvider`.

## API
### Create top-up
`POST /api/v1/payments/wallet/top-up`

Headers:
`Authorization: Bearer <access-token>`
`Idempotency-Key: <unique-key-at-least-8-characters>`

Body:
```json
{"amount_rial": 100000}
```

Response includes `payment` and `redirect_url`. The client must redirect the browser to that URL.

### Callback
Zarinpal returns to the configured callback URL. The callback URL contains a payment id and random token generated by the server. The backend checks both, checks the returned authority against the stored authority, and verifies the transaction server-to-server before crediting the wallet.

### Payment status
`GET /api/v1/payments/{payment_id}` (owner only).

## Setup
1. Copy the files in this package into the matching paths in the project.
2. Add the environment values from `.env.phase4.example` to `.env`.
3. Set `ZARINPAL_SANDBOX=true` while testing. Use the merchant id issued for the selected environment.
4. Set `PAYMENT_CALLBACK_BASE_URL` to a publicly reachable HTTPS URL in staging/production. Localhost callbacks do not work from the gateway.
5. Add `httpx` to runtime dependencies only if your own application needs it; this implementation uses Python standard library networking.
6. Run:
   `uv run alembic upgrade head`
   `uv run pytest -q`

## Important production checks
- Never set sandbox false until the live merchant id and live callback URL are configured.
- Do not trust callback `Status` as proof of payment. It only determines whether the backend should call Verify.
- Do not credit the wallet from the browser redirect or request response.
- Keep the callback endpoint reachable over HTTPS.
- The callback token is a random per-payment capability. Do not log full callback query strings or expose them in analytics.
- Configure rate limits at the reverse proxy/API gateway for payment creation and callback endpoints.
- Configure a frontend return page separately if the client needs a polished UX; do not accept arbitrary redirect URLs from requests.
- The Zarinpal sandbox and live merchant credentials are not interchangeable.

The installer locates the existing Alembic `versions` directory under `src/data` rather than assuming a fixed folder name. It creates a timestamped backup of the files it replaces.
